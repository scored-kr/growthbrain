# 선호도 키 별칭과 충돌 처리

챕터35는 제한된 명시 사전만 사용한다. 일반 자연어 의미 모델이나 자동 병합기가 아니다.

| 조회 기준 키 | 함께 취급하는 저장 키 |
| --- | --- |
| language | response_language, output_language |
| tone | response_tone, output_tone |
| format | response_format, output_format |
| code_style | coding_convention |

저장된 원래 key/값/출처는 유지한다. MCP 조건·검색의 key는 기준 키이며 달라졌을 때
storedKey를 함께 반환한다. coding.indentation 등 나머지 키는 서로 합치지 않는다.
업무 조건은 승인된 applicability.taskTypes로 결정하며 키 이름으로 추정하지 않는다.

현재 요청 > 한 프로젝트 > 공통 순서를 별칭에도 동일하게 적용한다. 현재 요청에 같은 의미의
키 두 개가 다른 값을 지정하면 AMBIGUOUS_REQUEST_CONDITIONS로 거절하고 선택을 요청한다.
같은 값이면 한 조건으로 반환한다. 요청은 저장되거나 후보로 자동 승격되지 않는다.

기존 금고에 같은 범위·업무의 별칭들이 동시에 활성일 수 있다. 조회/검색은 임의로 하나를 고르지
않고 해당 조건을 제외한다. keyConflicts는 기준 키·범위·기억 ID만, keyConflictCount는 총수를
반환한다. 상세 목록은 최대50개다. 충돌한 값·출처는 현재 조건으로 반환하지 않는다.
프로젝트 충돌을 무시하고 공통값으로 되돌아가지 않는다. 명시 요청이나 유효한 프로젝트 조건이
공통 충돌을 덮을 수 있다. 특정 업무 예외가 유효하면 같은 키의 일반 기본값보다 우선한다.

로컬 검토에서 별칭 후보도 동일한 충돌로 표시한다. 대체 대상 ID를 명시해 승인하기 전에는
기존 값이 유지된다. 여러 기존 값과 충돌하면 승인을 거절하며 사용자가 불필요한 기억을 먼저
사용 중지하거나 후보의 업무 조건을 좁혀야 한다. 값이 같더라도 자동 확정·자동 병합하지 않는다.

내부 상태는 v9다. 별칭 간 supersedes 관계를 구버전이 이해할 수 없어 버전을 올렸다.
v1~v8을 엄격하게 읽고 원래 암호문을 pre-state-v9-*.enc로 보존한 후 변경한다.
암호문 envelope v1/v2와 분할 저장 형식 v1은 별개이며 변경하지 않았다.
Git revert는 v9 금고를 v8로 되돌리지 않는다. 사용자 금고를 이 개발 실행기에서 열지 않는다.

검증: 별칭 우선순위/요청 모호성/출처 유지/명시 교체/다중 충돌/작업별 예외/다른 프로젝트 격리,
v8 암호문 보존·v9 재개, 실제 stdio MCP 호출과 오류 계약. npm run test:personalization은
P01–P13의 엔진 의무만 보고하며 actualAiOutputs=0, controlArmComparison=not_run을 표시한다.
이는 양쪽 일반 채팅의 실제 모델 개인화·사실 정확성·대조군 우위 판정이 아니다.
