[구현 스펙](implementation-spec.md)과 ign8t 작업 기록에 반영한다.

## 제품 목표와 역할

AI가 사용자 기억을 직접 조회하고 개인화된 답변과 작업을 수행한다. 기록 저장,
요약 표시, 채팅창 수동 붙여넣기만으로 MVP 완료를 선언하지 않는다.

- ign8t MCP: 개발 프로젝트, 명세, 작업 보드 관리.
- Growth Brain MCP: 사용자의 기억을 AI에 연결하는 제품 기능.
- 제품 도구: `get_context`, `search_memory`, `propose_memory`에 해당하는 기능.
- AI가 추론하거나 제안한 기억은 후보로 저장한다. 사용자 승인 없이 확정 기억으로
  저장하거나 기존 사실을 대체하지 않는다.

## 기억 범위 및 유효성

- 공통 선호도는 언어, 답변 방식, 업무 스타일 등 계정의 기본값이다.
- 프로젝트 기억은 해당 프로젝트의 목표, 제약, 결정, 변경 이유, 출처, 진행 맥락이다.
- 모든 기억에 적용 범위와 출처를 명시한다. 프로젝트 발언을 자동으로 공통 선호도로
  승격하지 않는다.
- 조회는 공통 선호도와 선택한 프로젝트의 유효한 기억을 함께 조립한다.
- 충돌 우선순위: 현재 사용자의 명시적 요청 > 프로젝트의 명시적 조건 > 공통 기본 선호도.
- 다른 프로젝트 기억의 유출, 폐기·대체된 결정의 재등장을 차단한다.
- 승인 상태, 변경·대체 관계와 출처를 검증 가능하게 유지한다.

## 암호화와 사용자 경계

- 무료·유료 사용자에게 동일한 기억 본문 보호 수준을 제공한다.
- 회원별 저장 공간과 접근 권한을 격리하고 사용자가 자신의 기억 전체를 삭제할 수 있게 한다.
- 프로젝트 이름, 대화 원문, 출처, 기억, 공통 선호도는 사용자 측에서 암호화하며 서버에는
  암호문을 저장한다.
- 복구 키는 MCP 도구 인자·응답, AI 대화, 로그, 저장소에 넣지 않는다.
- 로그인과 잠금 해제는 AI에 비밀값을 전달하지 않는 별도 사용자 흐름에서 처리한다.
- 사용자 기기의 로컬 MCP가 해독·검색하는 경로를 먼저 검증한다. 클라우드 개발 환경을
  제품의 실제 키·기억 엔진 실행 위치로 혼동하지 않는다.
- 웹·원격 MCP는 같은 보안 원칙을 유지하는 구조를 별도로 검증하기 전 지원 완료로
  표시하지 않는다. 서버에서 평문을 처리하면 운영자가 읽을 수 없다고 주장하지 않는다.
- AI에 전달된 맥락은 해당 AI 서비스가 읽을 수 있다. 이 보호 범위를 사용자에게 설명한다.

## 실제 AI 클라이언트 연동

- Codex와 Claude Code의 최신 공식 문서 및 설치 버전을 확인한다.
- 각 클라이언트가 실제 지원하는 MCP·훅·스킬·확인 UI를 사용한다. 동일한 훅이나 팝업을
  지원한다고 가정하지 않는다.
- 첫 클라이언트에서 전체 흐름을 완성한 뒤 두 번째 클라이언트로 확장한다.
- 초기 연결, 잠금 해제, 기억 저장 검토에 필요한 확인을 지원되는 UI에 연결한다.
- MCP·훅·스킬 설정은 기존 항목을 보존하며 병합하고 설치·해제 방법을 제공한다.
- 사용자가 기억을 찾아 복사할 필요 없는 흐름을 구현한다. MCP 등록만으로 매번 자동
  호출된다고 주장하지 않는다. 실제 호출과 결과물 반영을 확인한다.

## Chrome 대화 수집 확장

- 사용자가 동의한 AI 사이트의 대화를 선택한 프로젝트에 수집한다.
- 사이트별 동의, 수집 중지, 프로젝트 선택, 중복 방지를 지원한다.
- ChatGPT·Claude 등 사이트별 어댑터를 분리하여 다른 서비스로 확장할 수 있게 한다.
- 수동 맥락 붙여넣기는 제품용 MCP를 대체하지 않는다.
- MCP 연결이 AI 서비스의 전체 대화 수집 권한이나 자동 수신을 제공한다고 가정하지 않는다.

## MVP 합격 시나리오

새로운 AI 작업 세션에서 사용자가 “지난번 정한 조건대로 다음 작업을 진행해줘”라고
요청하면 AI가 실제 MCP 도구를 호출하여 공통 선호도와 현재 프로젝트의 최신 결정을
조회하고 해당 조건을 반영한 작업 결과물을 만든다.

검증 항목:

1. 수동 복사·붙여넣기 없이 새 세션에서 실제 도구 호출이 발생한다.
2. 도구 호출 기록과 결과물에서 기억의 반영을 확인한다.
3. 변경된 결정은 최신 유효 결정만 적용한다.
4. 상충하는 선호도는 정의된 우선순위를 적용한다.
5. 다른 프로젝트의 기억을 읽거나 섞지 않는다.
6. 잠긴 금고에서 기억이 유출되지 않는다.
7. 승인되지 않은 후보가 확정 기억으로 사용·저장되지 않는다.
8. 모의 테스트, 실제 MCP 전송 검증, 실제 AI 클라이언트 검증을 구분한다.
9. 설정 파일 생성만으로 클라이언트 연동 완료를 보고하지 않는다.

앱 셸과 화면 꾸미기는 최소화하고 기억 엔진과 연결 흐름을 우선한다.

최종 보고는 구현한 기능, 실제 검증 범위, 남은 제약, GitHub 백업 상태를 구분한다.

## 후속 명시 요구: 자동 수집과 공통 중심 계층

- Codex와 Claude Code 대화를 공식 훅으로 자동 수집한다. MCP 등록/스킬 안내만으로 수집을 대체하지 않는다.
- 공통 저장소가 메인이며 프로젝트별 저장소/색인은 그 아래에 둔다. 조회는 항상 공통을 먼저 거친다.
- 명시 프로젝트 또는 사용자가 지정한 트리거가 있으면 해당 프로젝트를 추가 조회한다.
  복수 매칭은 혼합하지 않고 선택을 요청한다. 임의 프로젝트 이름 추측/전역 승격은 하지 않는다.
- 공통/프로젝트 색인을 분리하고 검색 순위·정확도를 검증한다. 색인 존재만으로 의미 이해나 답변 정확도를 보장하지 않는다.

## 2026-11-04 추가 우선순위: 맥락 인계

사용자는 “맥락 인계가 중요함”을 핵심 가치로 재강조했다. 다음 AI/세션이 같은 프로젝트의
일을 이어가는 결과를 제품 평가의 중심에 둔다. 이를 구체화한 검증 항목은 목표, 최신 결정과 이유,
완료한 일과 근거, 미해결/차단 상태, 다음 행동이다. 단순 선호도 조회와 원문 수집만으로 인계 완성을 주장하지 않는다.
공통을 먼저 읽는 구조, 프로젝트 격리, 명시 요청 우선, 후보 승인, 폐기/대체 이력 배제는 유지한다.
장기 선호도와 작업 상태의 최신성/대체 규칙은 구분해야 하며, AI의 완료 주장을 확인된 사실로 자동 승격하지 않는다.
현재 구현 범위와 차이는 [제품 실사](product-diligence-2026-11-04.md)에 기록한다.

## 2026-11-05 최상위 목표 명확화: 선호도 기반 개인화

사용자는 단순 메모리 계층이 아니라 **선호도로 개인화되는 결과**를 North Star로 명시했다.
맥락 인계는 다음 세션·AI에서도 이 개인화와 일을 이어 주는 수단이다. 기존 인계 요구를 폐기하거나
검색/수집 완료만으로 개인화를 완료 처리하지 않는다.

- 공통 선호도를 먼저 검토하고 선택 프로젝트 조건·현재 요청과 결합한다. 업무에 적용할 조건과 예외를
  구분하며 일회 요청이나 프로젝트 교정을 계정 전체 선호도로 자동 승격하지 않는다.
- 개인화는 문체뿐 아니라 사용자가 명시한 업무 방식·판단 기준을 포함할 수 있다. 성격·민감 특성을
  임의로 추론·확정하거나 사실 정확성을 포기하는 의미가 아니다.
- 현재 key 기반 우선순위/검색과 후속 업무별 적용 조건·교정 효과 측정은 구분한다.
- 제안 지표는 주간 ‘선호도 재설명·수정 없이 채택한 작업’ 수이며, 실제 MCP/결과 증거·작업 품질·
  범위 안전성과 함께 확인한다. 아직 계측/검증된 지표가 아니다.
- 기본 AI 맞춤 지침과 Mem0/OpenMemory 등도 선호도 개인화를 제공한다고 설명한다. 동일 정보·모델의
  대조 없이 차별화·결과 우위를 주장하지 않는다.

구체적인 [경쟁·소스 비교](preference-personalization-review-2026-11-05.md)와
[평가안/합격 사례](personalization-evaluation.md)를 후속 구현의 기준으로 삼는다.
