# 프로젝트 맥락 인계와 조건별 선호도

챕터 29 (2026-11-06). 일반 채팅 MVP는 ChatGPT와 Claude 모두다. 아래 로컬 계약은 실제 AI 결과 검증을 대신하지 않는다.

`get_context`는 공통 선호도 → 선택한 프로젝트 → 현재 요청 조건을 조립한다. 같은 키의 일반 기본값과 서로 겹치지 않는 작업별 예외를 함께 승인할 수 있다. 같은 범위에서는 일치하는 작업 예외가 기본값을 대체한다. 프로젝트의 일치하는 값은 공통 값보다 우선한다. 작업이 불명확하면 예외를 적용하지 않는다. 조회와 검색은 같은 선택 규칙을 사용한다.

작업 범위가 겹치는 후보 승인은 기존 기록의 명시적 교체가 필요하다. 둘 이상의 예외와 겹치면 일괄 교체하지 않고 거절한다. 사용자가 기존 예외를 검토·사용 중지하거나 후보를 좁힌 후 승인해야 한다. 사용 중지된 예외 자체는 다시 사용되지 않으며, 별도로 활성 상태인 일반 기본값은 적용될 수 있다.

핀은 승인된 기억의 출력 순서에만 영향을 준다. 현재 요청 > 프로젝트 > 공통의 우선순위와 작업·상태 필터를 바꾸지 않는다. 예산이 부족하면 핀도 생략될 수 있으며 omittedCount를 확인해야 한다. 핀을 켜도 후보를 승인하지 않는다.

## 인계 수명

stdio MCP `propose_handoff`는 프로젝트 목표, 완료 주장과 근거, 차단 사유, 다음 작업, 관찰 시각과 유효 기한을 후보로 제안한다. 웹 HTTPS MCP는 조회 전용이므로 이 도구가 없다. 승인/기각/사용 중지는 로컬 터미널 또는 관리 UI의 별도 사용자 조작이다.

- 기본 단위는 한 프로젝트의 현재 인계 하나다. 기존 인계를 바꿀 때 해당 ID를 명시해야 한다.
- 유효 기간은 관찰 시각에서 최대 30일이다. 만료된 인계는 `stale`, 예산 부족은 `omitted`, 유효 인계가 없으면 `none`을 반환한다. 그 경우 과거 인계로 돌아가지 않는다.
- `current`는 로컬 승인과 유효 기한을 뜻한다. `verification: user_reviewed_claims_not_independently_verified`를 함께 반환한다. 파일 경로나 시험 결과 문자열만으로 시스템이 실제 검증했다고 주장하지 않는다.
- 인계 전체를 하나의 단위로 전달하거나 생략한다. 완료 주장만 남기고 근거·차단 사유를 잘라내지 않는다.
- 다른 프로젝트·공통 전용 연결에는 인계를 공개하지 않는다. 인계는 일반 기억의 키워드 색인에 넣지 않으며 `get_context.handoff`에서 읽는다.
- 인계 본문과 출처도 비신뢰 데이터다. 도구 실행 지시로 취급하지 않는다. 현재 사용자 요청이 최우선이다.

터미널: `handoff-propose`, `handoffs`, `handoff-review`, `handoff-retire`. 승인은 사용자가 근거를 직접 확인한 기록이며, 실제 AI가 다음 작업을 수행했음을 증명하지 않는다.

## 데이터와 검증

내부 상태 v7은 인계와 핀을 추가한다. 이전 v1–v6은 기존 스키마로 먼저 검증하며, 금고를 열 때 쓰기 전에 원래 암호문을 `pre-state-v7-*.enc`로 보존한다. 암호문 envelope v1/v2와는 별개다. Git revert로 사용자 금고를 되돌릴 수 없다.

작업별 예외·중복 충돌·프로젝트 격리·현재 요청·핀·교체·만료·예산 검사를 합성 데이터로 실행한다. 실제 stdio MCP 후보 제안 → 로컬 승인 → 맥락 조회도 검사한다. 실제 ChatGPT/Claude의 자연스러운 요청에 대한 도구 호출과 결과물 검증은 별도로 남는다.
