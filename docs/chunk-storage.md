# 금고 분할 저장과 암호문 증분 패키지

챕터32에서 도입했고 현재 내부 상태는 챕터35의 v9다. 기존 전체 백업 envelope v1/v2, 분할 저장 형식 v1, 내부 기억 상태 버전은 서로 다른 번호다.

## 사용자 전환

기존 금고를 사용자가 로컬 터미널에서 연 뒤 `storage-upgrade`와 `UPGRADE`를 입력한다. 현재 전체 암호문을 `pre-state-v9-*.enc`에 먼저 보존하고 저장 형식을 전환한다. 이 명령을 하지 않은 금고는 기존 전체 파일 저장을 유지한다. Git revert는 데이터 형식을 되돌리지 않는다. 이전 버전으로 돌아가야 한다면 보존한 전체 백업을 **새 디렉터리**에 복원한다.

`vault.json`은 인증된 암호화 manifest, `objects/*.json`은 불변 AES-256-GCM 암호문 조각이다. 프로젝트 이름·기억·원문·출처·상태·개별 기록 ID·검색용 메타데이터는 모두 암호화된다. 외부에 보이는 것은 소유자/저장소의 불투명 ID, 키 슬롯, 암호문 해시·크기·파일 수·변경 패턴이다. 접근 패턴 은닉이나 저장 크기 은닉을 주장하지 않는다.

기록을 컬렉션별 256개 버킷으로 나누어 바뀐 버킷만 새 nonce로 암호화한다. 전체 상태의 검증·승인·교체 규칙과 원래 기록 순서를 유지한다. 검색 색인은 여전히 잠금 해제된 기기 RAM에만 존재한다. 시작 시 전체 금고를 복호화하며, 필요한 조각만 지연 복호화하는 기능은 아니다.

조각을 먼저 안전하게 기록·동기화한 뒤 암호화된 manifest를 원자적 rename으로 교체한다. manifest에 포함되지 않은 조각은 현재 데이터로 읽지 않는다. 저장소 락으로 같은 기기의 쓰기를 직렬화하고, 현재 head hash를 다시 확인해 오래된 스냅샷의 덮어쓰기를 거절한다. 이는 분산 DB의 CAS나 다중 기기 자동 병합이 아니다. 커밋 후 디렉터리 동기화 결과가 불확실하면 세션의 후속 읽기/쓰기를 차단하고 재개방을 요구한다.

## 증분 파일 흐름

- `storage-export`: 새 암호문 파일 경로, 이전 checkpoint 파일(없으면 전체 스냅샷), 새 checkpoint 파일을 지정한다. checkpoint는 암호문 해시만 포함한다. 받는 쪽이 실제 적용한 checkpoint를 기준으로 다음 변경분을 만든다.
- 전체 스냅샷(delta `base: null`)은 기존 `restore <새 디렉터리> <파일>` 명령으로 새 기기에 복원할 수 있다. 올바른 금고 비밀번호와 모든 조각이 필요하다.
- `storage-apply`: 파일을 선택하고 `APPLY`로 확인한다. 현재 head와 일치하는 기준점, 인증된 과거 head 목록, 증가한 revision, 소유자/저장소, 모든 조각의 해시·인증 태그와 전체 상태 불변식을 먼저 검증한다. 누락·변조·다른 분기·재전송이면 현재 manifest를 바꾸지 않는다.
- 마지막 128회 커밋의 과거 head를 암호화해 보존한다. 너무 오래된 checkpoint는 거절한다. 양쪽에 독립 변경이 있으면 자동으로 어느 쪽을 덮어쓰거나 합치지 않는다. 각 전체 백업을 보존하고 검토해야 한다.
- 복구 키 재발급은 데이터 키를 회전하므로 전체 스냅샷/백업을 새로 발급한다. 서로 다른 데이터 키의 증분을 자동 적용하지 않는다.
- `storage-prune`과 `PRUNE`은 현재 manifest에서 참조하지 않는 암호문과 예약된 임시 쓰기 파일을 제거한다. 먼저 모든 대상의 파일 종류·권한·소유자·해시를 검증한다. symlink나 알 수 없는 파일은 거절한다.

`backup`은 계속 독립적인 envelope v1/v2 전체 백업을 만든다. 비밀번호 분실 복구는 이 전체 백업과 별도 복구 파일을 사용한다. 증분 파일 하나를 유일한 복구 수단으로 보관하면 안 된다. 전체 원문 제한은 11MiB로 유지하여 기존 전체 백업 크기 제한을 넘지 않게 한다. 분할 저장이 저장 용량 무제한을 의미하지 않는다.

이 기능은 기기에서 암호문을 만드는/검증하는 계층이다. 자동 네트워크 동기화, Supabase 저장/RLS, 원격 계정 삭제는 연결하지 않았다. 저장소 자체를 과거 전체 상태로 바꾼 공격을 외부의 신뢰 가능한 기준점 없이 재시작 후 탐지한다고 보장하지 않는다.

## 검증

합성 금고 100개 기억 중 하나를 바꿨을 때 새 조각 1개만 생성되는지 검사한다. 전체 복원→여러 커밋의 증분 적용, 분기 충돌과 변조된 기준점, 조각 누락/변조, head 발행 전 중단 상태의 복원, 낡은 쓰기 거절, 복구 키 회전/전체 복구, symlink/알 수 없는 파일, 임시 조각 정리, 로컬 삭제 시 명시 내보내기 보존을 확인한다.

실제 PTY에서도 분할 전환→전체 스냅샷 내보내기→추가 변경→증분 내보내기→별도 금고 복원/적용→비밀번호 분실 복구를 검증한다. 강제 전원 차단이나 실제 두 사용자 기기의 네트워크 시험은 아니다.
