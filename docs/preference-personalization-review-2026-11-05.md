## 1. 무엇을 개인화할 것인가

제안하는 제품 약속: **“어떤 AI로 일하든, 내가 원하는 방식과 판단 기준을 다시 설명하는 수고를 줄인다.”**
현재 모든 AI에서 작동한다는 지원 범위 광고가 아니라 검증할 제품 방향이다.

| 구분 | 합성 예시 | 처리 원칙 |
| --- | --- | --- |
| 공통 선호도 | 결론부터, 불확실한 수치는 가정이라고 표시 | 사용자가 공통 기본값으로 승인한 규칙 |
| 업무별 선호도 | 캠페인 제안은 실행안 3개와 측정 방법 포함 | 해당 작업에서만 적용할 조건이 필요 |
| 프로젝트 조건 | 고객 A는 격식체·할인 표현 금지, B는 친근한 문체 | 선택한 프로젝트 안에서만 적용 |
| 현재 요청 | 이번 답변은 영어로 자세히 설명 | 이번 작업에 우선하고 장기 선호도를 덮어쓰지 않음 |
| 사실·진행 상태 | 예산 100만 원, 검토 대기, 다음은 이메일 초안 | 선호도와 구분해 정확성·최신성 확인 |

문체뿐 아니라 비교 기준·근거 요구·업무 순서도 개인화 후보지만, 이 구분과 UI는 제안이다.
사용자가 한 번 고친 문장을 성격·소득·건강·정치 성향으로 확대 해석하지 않는다.
반복했다고 공통 선호도로 자동 확정하지 않으며, 개인화가 사용자의 사실 오류에 동조하는 이유가 되지 않는다.

예: 공통은 ‘결론 먼저·과장 금지’, A는 ‘격식체·할인 금지’, 현재 요청은 ‘이번에는 영어’다.
성공은 새 세션에서 영어·격식체로 과장/할인 없는 제안을 만드는 것이다. 다음 세션까지 영어를
영구 적용하거나 고객 B의 말투를 섞으면 실패다. ‘이메일 초안을 이미 만들었다’는 인계 기록만으로는
이 개인화가 달성되지 않는다. 모든 예시는 실제 사용자 프로필이 아닌 합성 조건이다.

## 2. 경쟁 비교

2026-11-05에 아래 공식 페이지를 확인했다. 경쟁 기능은 공식 설명이며 직접 설치·동일 과제로
성능을 검증한 결과가 아니다. 서로 다른 Mem0 API/확장/로컬 MCP의 기능·요금·보호 범위를 합치지 않는다.

| 비교 대상 | 공식 자료에서 확인한 개인화 방향 | Growth Brain에 주는 판단 |
| --- | --- | --- |
| [Mem0 / OpenMemory](https://mem0.ai/openmemory) | 코딩 선호·패턴 수집, user preference 유형, 프로젝트별 회수, 필요한 맥락 자동 전달, 변경·접근 관리 설명 | ‘단순 메모리 저장소’가 아니다. 선호도·프로젝트·자동 적용만으로 차별화 불가 |
| [Mem0 Chrome 확장](https://mem0.ai/blog/introducing-the-openmemory-chrome-extension) | 여러 AI에서 말투·작성 방식·선호도 활용 설명. 플랫폼별 자동/수동 동작이 다름 | 비개발자·여러 AI라는 범위도 독점 영역이 아님. 실제 설치와 교정 비용 비교 필요 |

| [ChatGPT 메모리](https://help.openai.com/en/articles/8590148-memory-in-chatgpt)·[맞춤 지침](https://help.openai.com/en/articles/8096356-chatgpt-custom-instructions) | 관련 선호도 활용과 사용자 지정 응답 지침 | 사용자가 이미 쓰는 기본 기능이 가장 가까운 대안. 별도 설치 부담을 상쇄해야 함 |
| [Claude 메모리](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context) | 소통/업무 방식, 기술 선호와 프로젝트별 기억 설명 | 기본 도구에는 프로젝트 분리가 없다는 가정도 피해야 함 |
| Growth Brain | 로컬 암호화, 명시 승인, 공통→선택 프로젝트, 현재 요청 우선, 출처·명시 대체·사용 중지, 제품 MCP | 이 조합의 구현은 있으나 더 잘 맞는 실제 결과·간편함·지불 의사는 아직 미검증 |

[OpenMemory 로컬 MCP 설명](https://mem0.ai/blog/introducing-openmemory-mcp)도 기기 내 저장을 내세운다.
‘우리만 로컬’, ‘경쟁사는 모두 사용자 기억을 서버에서 읽는다’고 주장할 근거가 없다. 로컬 저장,
모델로의 전송, 동기화, 삭제는 각각 확인해야 한다. Growth Brain도 AI에 보낸 맥락은 해당 AI가 읽는다.
[Mem0 현재 요금](https://mem0.ai/pricing)은 Free/Custom 및 한도·모델 키·초과 사용 조건을 구분한다.
무료 진입은 가격 압박 근거지만 전 기능·모든 비용이 영구 무료라는 뜻은 아니다.

**현재 차별화는 확정 사실이 아니라 가설이다:** 특정 반복 업무에서 승인한 선호도를 상황에 맞게 적용하고,
교정 뒤 같은 실수를 줄이며, AI를 옮겨도 사용자가 적게 관리하게 만든다. 경쟁 제품도 이 목표를 달성할 수 있다.
한국어, 로컬 암호화, MCP, 벡터 색인 어느 하나도 단독으로 모방 불가능한 우위가 아니다.

## 3. 현행 코드가 해 주는 것과 남은 것

| 단계 | 실제 소스 확인 | 남은 검증·구현 |
| --- | --- | --- |
| 수집→후보 | [classifier](../src/classifier.ts): 명시 발언을 보수적으로 추출, 프로젝트 후보, 임시/인용/불확실 문맥 제외 | 자연어 선호도 전반을 이해하는 학습기 아님. 실제 클라이언트 훅 실행 범위는 별도 검증 |
| 승인·기억 수명 | [model](../src/model.ts), [engine](../src/engine.ts): global은 preference, 후보/활성/폐기/대체, 출처와 이유 | 교정 결과를 사용자 만족과 연결하는 평가 기록 없음 |
| 공통·프로젝트 선택 | [memory-index](../src/memory-index.ts): active만 색인, 공통 기본값에 한 프로젝트를 덮어씀 | 우선순위는 동일 key 기준. 다른 key로 표현된 의미상 충돌을 일반적으로 해결한다고 볼 수 없음 |
| 맥락 조립 | getContext는 현재 요청→프로젝트→공통 순, 같은 범위 내 key 순으로 문자 예산 적용 | query는 프로젝트 라우팅에 쓰임. 업무별 적용 조건/중요도에 따라 선호도를 선별하는 엔진은 아직 없음 |
| 검색 | BM25/어휘+제한된 개념 보조, 승인된 현재값만 | 검색 점수는 선호 강도·정답 확률이 아님. Top1 개선이 개인화 결과 개선을 뜻하지 않음 |
| 결과 생성 | [제품 스킬](../integrations/codex/growth-brain/SKILL.md)에 실제 MCP 조회→조건 적용→후보 피드백 절차 | 스킬 문구는 실행 증거가 아님. 실제 새 세션 도구 호출+결과물+사용자 평가가 필요 |

후속 설계는 **공통 승인 프로필 검토 → 업무에 적용할 선호도 선택 → 명시/고유 트리거의 프로젝트 조건
결합 → 현재 요청 우선 → 실제 AI 결과 → 교정 후보 검토** 순으로 잡는다. 공통을 반드시 읽는 것과
공통의 모든 상세 내용을 매번 AI에 보내는 것은 다르다. 기본 언어 같은 항상 필요한 기본값은 검색
유사도가 낮다는 이유로 빠뜨리지 않고, 특정 작업의 상세 선호도는 적용 조건으로 제한해야 한다.
색인은 이 선택을 돕지만 승인·적용 범위·우선순위·교정의 의미를 대신하지 못한다.

이 흐름에 필요한 적용 조건, 예외, 의미상 충돌 처리, 결과 평가 계약은 후속 설계다. 이번 문서는
스키마·자동 승인 정책·데이터 마이그레이션을 바꾸거나 개인화를 위한 모델 재학습을 전제하지 않는다.

## 4. 제안하는 단일 North Star

**주간 ‘선호도를 다시 설명하거나 수정하지 않고 채택한 작업’ 수.**

이는 제품 방향을 운영 가능한 지표로 옮긴 제안이며 아직 계측·관측된 지표가 아니다.
성공 작업은 다음 조건을 모두 만족해야 한다.

1. 결과를 보기 전에 승인된 선호도가 관련 있는 작업으로 등록한다. 기본 요청만으로 끝나는 작업은 별도 분류한다.
2. 실제 MCP 호출 기록과 기억 ID/버전, 결과물에서 해당 선호도 적용을 확인한다. 현재 요청/프로젝트 예외를
   따르는 것이 정답인 경우는 기본값을 적용하지 않아도 성공할 수 있다.
3. 사용자가 결과를 채택하고 선호도를 다시 설명하거나 고칠 필요가 없었다고 확인한다.
4. 사전 정의한 핵심 작업 정답/품질 기준을 만족하고 다른 프로젝트·미승인·대체·폐기 기억의 혼입이 없다.
5. 하나의 작업과 수정본을 중복 집계하지 않는다. 답변 분할·메시지 수로 성공 수를 늘리지 않는다.

전체 대상 시도 수, 성공률, 평가 응답률, 활성 사용자당 분포를 함께 보고한다. 호출 실패도 대상 시도에
남기며, 피드백 미응답은 ‘모름’으로 표시한다. 미응답·설치 실패를 지워 성공률을 높이지 않는다.
채택만으로 개인화의 인과 효과가 증명되지는 않는다. [대조 실험](personalization-evaluation.md)으로 검증한다.

이번 단계의 핵심 실행 지표(OMTM)는 첫 지원 클라이언트의 **실제 MCP 조회+조건이 반영된 결과물** 확보다.
기존 Codex 검증은 인증401/호출0이었다. 이 문서 검토에서 재시도하거나 해결된 것으로 표시하지 않는다.

## 5. 스킬 관점의 반론과 가장 싼 검증

영향·틀릴 가능성·검증 용이성을 각각1~3의 주관적 우선순위로 점수화했다. 확률이나 실측이 아니다.

| 순위/점수 | 가장 강한 가설과 반론 | 최소 검증 / 중단·변경 기준 |
| --- | --- | --- |
| 1 / 3×3×3=27 | 사용자 선호는 변하고 프로젝트마다 달라 지속 관리 가치가 있다. **실패 조건:** 잘 쓴 맞춤 지침으로 같은 결과를 더 쉽게 얻음 | 동일 모델·동일 선호도로 고정 프로필과 비교. 탐색 파일럿에서 추가 성공도 순관리 시간 절감도 없으면 기능 확장 보류 |
| 2 / 3×2×3=18 | 명시 교정·승인으로 다음 결과를 개선할 수 있다. **실패 조건:** 승인 피로가 교정 감소보다 큼 | 다음 작업에서 같은 선호 오류 재발과 승인/설정 시간을 함께 측정. 순절약이0 이하이면 검토 UX부터 수정 |
| 3 / 3×2×2=12 | 여러 AI를 오가며 같은 기준을 적용할 일이 잦다. **실패 조건:** 고객의 실제 반복 업무가 한 AI의 기본 기능으로 충분함 | 기존 인터뷰 참가자의 최근 사례를 요청하는 연구안 준비. 반복 전환이 관찰되지 않으면 여러 AI를 핵심 유료 이유로 단정하지 않음 |
| 4 / 3×2×1=6 | 특정 업무의 우수한 결과와 쉬운 관리에 돈을 낸다. **실패 조건:** 기본 AI·OpenMemory와 차이를 체감하지 못함 | 도움 없는 사용과 자발적 재사용/유료 의사 확인. 의향만으로 수익성·잔존율 입증 금지 |

VC 관점에서는 ‘개인화 시장이 크다’보다 반복 사용·기본 기능 대비 개선·획득/지원 비용·모방 가능성을 본다.
AC 관점에서는 한 고객군·한 반복 업무에서 위 가설을 값싸게 검증할 수 있어야 한다.
선배 창업가 관점에서는 프로필 관리 부담이 실제로 줄어드는지가 관건이다. 스킬은 이 기준을 제공하며
실제 투자 심사나 시장 수요를 대신하지 않는다. 인터뷰4명·가상고객70/100·PDF 목표 수치는 여전히 구분한다.

## 6. 다음 작업의 경계

| 우선순위 | 작업 | 근거·크기 판단 |
| --- | --- | --- |
| Must | 한 클라이언트에서 기본 선호도+프로젝트 예외+일회 요청→MCP→결과 확인 | 실제 실행 차단 해결 필요. 일정은 인증/기기 조건 확인 전 확정 불가 |
| Must | 선호도의 적용/예외/교정 계약과 합성 합격 사례, 고정 프로필 대조 | 중간 규모 설계. 기존 key/승인/대체를 재사용하고 데이터 변경은 별도 검증 |
| Must | 결과 채택·반복 교정·설정/승인 부담 측정 | 작은 탐색 실험. 원문을 자동 중앙 수집하지 않음 |

| Could | 임베딩/재순위화·추가 연동·더 많은 선호도 유형 | 누락 원인이 검색이라는 관측과 결과 개선이 있을 때 |
| 이번 범위 밖 | 추정 성격 자동 확정, 무승인 공통 학습, 모든 AI 동시 지원, 장식형 대시보드 | 승인·범위 안전성과 첫 클라이언트 검증을 우선 |

보안상 교정 데이터와 평가 기록도 개인 정보다. 기억 본문·원문·프로젝트명·민감 추론을 분석 로그에
추가하지 않는다. 평가용 기록은 사용자 기기의 암호화 영역에 두며 실제 자료의 경쟁 서비스 전송은
연구 동의 범위에서만 한다. 각 AI가 받은 맥락, 로컬 삭제, 원격 회원 삭제는 별개다.

이번 확인은 공식 자료·소스·문서 정합성 검토다. 경쟁 제품 실설치, 실제 사용자 결과 비교,
첫 AI 클라이언트 개인화 성공, 개인정보 영향 평가나 독립 보안 감사 완료를 뜻하지 않는다.
