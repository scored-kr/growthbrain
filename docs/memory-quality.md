# 기억 추출과 검색 품질 개선 — 2026-11-04

## 챕터 13: 승인 전 후보의 정확성

수집 원문과 재사용할 기억 후보는 별개다. 기존 분류기는 `해줘`/`please` 같은 단어만 있어도
전체 메시지를 일반 feedback으로 잘라 저장했다. 질문·인용·일회성 요청에도 후보가 생겼고,
여러 조건을 한 key에 섞거나 4,000자 뒤의 예외/부정을 잘라낼 수 있었다.

현재 분류기는 명시한 언어, 어조, 형식, 대상, 예산, 기한, 브랜드, CTA를 안정된 key로 분리한다.
간단한 한국어/영어 답변 언어만 정규화하고 나머지는 원래 조건 문장을 값으로 보존한다.
금액/단위/기간/상한/부정을 요약하며 잃지 않는다. 문장별 발췌와 전체 원문 캡처 참조를 유지한다.
같은 key의 변경도 후보이며, 기존 확정 기억을 바꾸려면 명시적 대체 승인이 필요하다.

질문, 인용/예시, 조건부·미확정, 일회성 발언은 자동 후보 추출에서 제외한다. 코드 블록/인용 행도
제외한다. 분류되지 않은 단순 실행 요청은 기억으로 남발하지 않는다. 제한적으로 명시된 지속
피드백은 일반 후보로 남긴다. 서로 다른 조건이 너무 많거나 문장이 너무 길면 임의 절단하지 않고
후보 생성을 보류한다(32개 문장/8개 후보/후보 4,000자). 원문은 기존 캡처 제한 안에서 보존한다.

이것은 보수적인 로컬 규칙이며 일반 자연어 이해가 아니다. 조건부 표현이 섞인 메시지 전체를
보류할 수 있고, 새로운 표현은 누락될 수 있다. 모든 후보는 프로젝트 범위/미승인 상태이며
공통 자동 승격, 자동 확정, 외부 AI 전송, 기존 저장 기억의 자동 재분류는 없다.
상태 v4/envelope v1/v2는 바꾸지 않는다.

`npm run test:extraction`으로 개발용 합성 44발언을 재현한다. 구현 전/후 동일한 22개 양성
발언의 정확한 조건 key 분류는 2→22, 22개 음성 발언의 후보 오탐은 17→0이다. 부정·상한·출처,
상충하는 후보 승인과 원문 보존을 별도 회귀 검사한다. 개발에 사용한 사례이므로 실사용 정확도나
미지의 표현에 대한 일반화 수치로 해석하지 않는다. 실제 사용자 자료는 동의 후 별도 평가가 필요하다.
