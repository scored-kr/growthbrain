# Windows에서 같은 계정으로 두 PC 이어 쓰기

## Windows 설치 시험 보류

현재 Windows 설치 시험본은 다운로드와 설치를 보류한다. 이미 보안 프로그램이 파일을 격리했다면 그대로 둔다. 실시간 보호가 켜진 Windows 표준 사용자 환경에서 다운로드와 정상 설치를 확인한 뒤 이 안내를 갱신한다.

아래 두 PC 시험에는 계정 연결을 준비한 설치 파일, Windows 11 x64 두 대, Growth Brain 시험 계정 두 개, 사용자 지정 MCP 연결을 허용하는 ChatGPT·Claude 웹 계정이 필요하다. 재개 후 개인 기억 대신 아래 예시를 사용한다.

## 한 PC에서 ChatGPT 대화를 Claude로 이어받기

설치 시험 재개 후, 계정과 기기 연결이 준비된 PC 한 대에서 확인한다.

1. 앱의 **대화 수집 (선택)**에서 Chrome을 연결한다. 확장에서 ChatGPT 사이트와 시험 프로젝트를 선택하고 수집에 동의한다.
2. ChatGPT 대화에서 “이번 뉴스레터 이름은 라임우체통으로 하자”라고 말한다. 확장에 생긴 후보의 출처와 프로젝트를 확인하고 승인한다.
3. 앱의 **ChatGPT·Claude 연결**에서 Claude를 연결하고 같은 프로젝트의 읽기를 승인한다. Claude 웹의 새 일반 채팅에 “지난번 정한 뉴스레터 이름으로 첫 호 제목 세 개 써줘”라고만 보낸다.
4. Claude의 `get_context` 호출, 해당 연결의 기기 조회 기록, 첫 답변에 반영된 뉴스레터 이름을 함께 확인한다. 앱을 켜 둔 상태에서 반대 방향도 시험하려면 Claude 수집과 ChatGPT 읽기를 각각 승인하고 새로운 이름으로 반복한다.

## PC A에서 승인한 뒤 완전히 종료

1. Growth Brain에 로그인한다. 처음 쓰는 시험 계정은 **계정 만들기**에서 가입하고, 필요한 경우 메일의 확인 코드를 제출한다. 개인 PC에서 다음 실행에도 로그인을 유지하려면 **이 개인 PC를 신뢰하고 다음에 자동 로그인**을 선택한다.
2. **프로젝트와 기억 편집**에서 공통 범위를 선택한다. 항목 ‘답변 언어’, 값 **한국어로 답변**을 입력하고 **기억 검토 후 저장**을 눌러 승인한다.
3. 프로젝트 ‘캠페인’을 만든다. 그 프로젝트의 ‘캠페인 채널’에 ‘포스터 사용’을 승인한 뒤 같은 항목을 **뉴스레터 사용**으로 바꾸고 교체를 확인한다. 격리 대조에 사용할 별도 프로젝트 ‘타 프로젝트’에는 ‘기념 배지 제작’을 저장한다.
4. **내 선호도와 프로젝트**에서 ‘캠페인’에 적용되는 두 조건과 동기화 완료 표시를 확인한다. 실패나 충돌이면 A를 계속 켜 둔 상태에서 원인을 확인한다. 완료 시각을 기록한 뒤 Windows **전원 → 종료**로 A의 전원을 끈다. 나머지 시험 동안 A는 꺼 둔다.

## PC B에서 처음 로그인

1. 새 설치에서 같은 계정으로 로그인한다. **내 선호도와 프로젝트**에서 ‘캠페인’을 선택해 공통 언어와 뉴스레터 결정이 표시되는지 확인한다. 로그인 이후 파일이나 별도 비밀번호를 요구했으면 해당 화면을 기록한다.
2. **ChatGPT·Claude 연결**에서 이번에 시험할 서비스만 선택한다. 연결이 필요한 때 앱이 안내하는 해당 서비스 설정에서 Growth Brain과 OAuth를 선택한다. 서비스가 주소를 요청하면 앱의 연결 주소를 사용한다. **연결 승인·철회**에서 요청 번호를 브라우저와 대조하고 ‘캠페인’ 범위의 읽기를 승인한다. 나머지 서비스에서 이 과정을 한 번 더 진행한다. 대화 수집은 이 시험에 필요하지 않다.
3. ChatGPT의 **새 일반 채팅**, Claude의 **새 일반 채팅**을 각각 연다. 이전 채팅 내용이나 사용자 지정 지침이 결과에 영향을 주지 않는 시험 계정을 쓴다. 두 채팅에 각각 아래 한 문장만 보낸다.

> 지난번 정한 조건대로 다음 작업을 진행해줘

| 서비스 | 기록할 증거 | 합격 조건 |
| --- | --- | --- |
| ChatGPT | 서비스가 표시한 도구 호출, 해당 연결의 앱 조회 이력, 실제 첫 답변 | 자연어 요청으로 `get_context`를 호출하고 한국어로 구체적인 뉴스레터 다음 작업을 제안 |
| Claude | 서비스가 표시한 도구 호출, 해당 연결의 앱 조회 이력, 실제 첫 답변 | 동일 |

4. 두 도구 결과에서 공통 조건과 현재 프로젝트의 최신 결정을 확인한다. 타 프로젝트의 ‘기념 배지 제작’, 교체한 ‘포스터 사용’, 검토 대기에 있는 후보는 결과에서 빠져야 한다. 수동 도구 선택이나 조건 재입력으로 성공했다면 최초 시도의 결과와 따로 기록한다.
5. 같은 B에서 로그아웃하고 두 번째 Growth Brain 계정으로 로그인한다. 첫 계정의 프로젝트·선호도가 조회되지 않아야 한다. 이전 서비스 연결로 재조회가 거부되는지, 두 번째 계정에서 새로 승인한 범위만 조회되는지 확인한다. 이어서 한 서비스의 연결을 철회하고 새 조회가 거부되는지 확인한다. 이때 이미 전달한 채팅 기록은 해당 AI 서비스에 남는다.

계정, 비밀번호, 코드, 토큰을 화면 캡처에서 가리고 PC 종류·설치 파일 SHA·A 종료 시각·서비스별 요청 시각과 결과만 전달한다. 취소·재연결이 필요했다면 실제로 누른 버튼을 함께 기록한다. 비밀번호 재설정은 인증 자격을 바꾸며 기존 기억을 여는 원래 키를 재발급하지 않는다.

서비스별 설정 위치는 공식 안내에서 확인할 수 있다. [ChatGPT 사용자 지정 MCP](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt) · [Claude 사용자 지정 커넥터](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)

## 두 기기가 모두 오프라인에서 편집한 경우

1. 같은 시험 계정으로 A와 B에 로그인하고 같은 프로젝트에서 **동기화 완료**를 확인한다. 앱을 열어 둔 채 두 PC의 네트워크를 끈다. A에는 새 공통 선호도 한 개, B에는 다른 이름의 프로젝트 결정 한 개를 승인한다. **기기에 저장됨**은 해당 PC에 편집 내용이 보관됐다는 뜻이다.
2. A와 B를 차례로 재연결한다. 양쪽에서 **동기화 다시 확인**을 누르고 두 항목이 모두 보이는지 확인한다.
3. 다시 연결을 끊고 두 PC에서 같은 프로젝트의 같은 결정을 서로 다른 값으로 수정·승인한다. 재연결한 뒤 변경 확인 화면에서 **양쪽 변경 비교**를 누른다. **이 기기의 값**과 **계정에 동기화된 값**을 확인해 하나를 고른 뒤 **선택한 값으로 동기화**를 누른다. 검토 중인 PC는 AI 조회를 일시 중지한다.
4. 다른 PC에서 **동기화 다시 확인**을 누른다. 두 PC 미리보기와 새 MCP 조회에 선택한 값이 나오는지 확인한다. 검토 중 다른 기기에서 수정했다는 안내가 나오면 최신 두 값을 다시 비교한다.

이 시험의 목표는 새 ChatGPT 대화와 새 Claude 대화가 각각 기기의 금고에서 승인한 조건을 읽고 실제 답변에 반영하는지 확인하는 것이다. Windows 11 x64 표준 사용자 계정, 로컬 NTFS 사용자 프로필, 인터넷 연결을 사용한다. 시험용 금고에는 아래 예시처럼 가상의 내용만 넣는다.

이전 시험본 `b149ef1`은 로컬 출처가 AI 조회에 포함되던 버전이다. 이번 개인정보 검증에는 출처 분리를 적용한 새 설치 파일을 사용한다.

### 설치와 준비

1. 전달받은 `GrowthBrain-Setup-x64.exe`를 실행한다. **예**를 선택해 현재 사용자 계정에 설치하고 앱을 연다. 이 시험 파일은 코드 서명 전 산출물이다. Windows 또는 조직 정책이 실행을 차단하면 화면의 표시를 기록하고 중단한다.
2. Growth Brain에서 12자 이상의 새 비밀번호를 두 번 입력해 금고를 만든다. 다음 실행부터는 같은 비밀번호로 연다. 시험용 비밀번호는 기기에서만 입력한다.
3. **기억과 프로젝트**에서 공통 범위를 고르고 **답변 형식**에 “항상 세 줄의 표로 제시”를 입력한다. **기억 검토 후 저장**에서 승인한다. “겨울 캠페인” 프로젝트를 만든 뒤 그 범위에서 **캠페인 채널**을 처음에는 “블로그”로 저장한다. 같은 항목을 “뉴스레터”로 다시 저장하고 기존 값을 교체하는지 확인한 뒤 승인한다. 다른 프로젝트 “봄 캠페인”에는 “비공개 봄 채널”을 저장한다.
4. **서비스 연결 → 공개 연결 시작**을 누른다. 처음에는 **Tailscale 연결 설정 열기**에서 로그인하고 이 기기의 연결을 허용한다. HTTPS와 Funnel을 사용할 수 있는 Tailscale 계정이 필요하다. 앱이 인증서를 준비하고 외부 HTTPS 주소를 검사한다. 주소가 표시되면 **서비스에 등록할 주소 복사**를 누른다. 신규 주소가 DNS에 반영되기까지 몇 분 걸릴 수 있다. 조직 정책으로 승인이 거부되면 관리자에게 표시된 상태를 전달한다. [Tailscale Funnel 조건](https://tailscale.com/docs/features/tailscale-funnel)
5. 아래 등록을 ChatGPT와 Claude에서 각각 한 번씩 진행한다. 앱과 금고를 열어 둔다. **연결 승인·철회**에서 브라우저와 앱의 요청 번호, 서비스 콜백 주소, 읽기 범위를 확인하고 **겨울 캠페인**을 선택한다. 승인하면 서비스가 공통 기억과 해당 프로젝트의 기억을 읽을 수 있다. 서비스로 돌아가 인증을 마친다. 앱의 **서비스 인증됨**은 코드 교환이 끝났다는 표시다.

### ChatGPT와 Claude 등록

| 서비스 | 등록 화면과 선택 | 계정·워크스페이스 조건 |
| --- | --- | --- |
| ChatGPT 웹 | 앱의 **ChatGPT 앱 설정 열기** → Plugins의 **+ → Add custom MCP server**. 이름에 Growth Brain을 입력하고 복사한 HTTPS 주소와 OAuth를 선택한다. 클라이언트 등록 방식이 보이면 동적 등록(DCR)을 선택한다. 경고를 읽고 생성한 플러그인을 자신의 계정에서 사용할 수 있게 한다. 이전 화면은 Settings → Apps → Create다. | Pro의 읽기 연결과 Business·Enterprise/Edu의 권한이 있는 계정이 대상이다. [공식 등록 안내](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp) |

금고의 읽기 연결만 시험하려면 여기까지 준비하면 된다. Chrome에서 대화를 수집하려면 별도로 앱의 **대화 수집 (선택)**을 열고 현재 사용자용 Chrome 연결을 등록한다. Chrome 정책이 허용하는 기기에서 앱이 여는 확장 폴더를 로드하고, 확장 팝업에서 수집할 사이트와 프로젝트를 선택해 동의한다.

### 선택 사항 — 백업과 복구 시험

열린 금고의 **백업·복구 파일**에서 현재 비밀번호를 확인해 복구 파일을 발급한 뒤 **새 암호화 백업**을 저장한다. 파일은 현재 Windows 사용자 프로필 안의 서로 다른 비공개 NTFS 폴더에 새 이름으로 저장한다. 복구 파일과 발급 후 만든 백업이 함께 있으면 새 비밀번호로 복원할 수 있으므로 따로 보관한다. 일반 백업은 원래 비밀번호로도 복원할 수 있다.

새 Windows 프로필 또는 새 기기에서 두 파일을 각각 비공개 폴더로 옮긴다. 금고를 만들기 전에 시작 화면에서 복원 방식을 고른다. 원래 비밀번호로 복원할 때는 백업 파일을, 비밀번호를 잃어버린 경우에는 백업과 복구 파일을 선택하고 새 비밀번호를 두 번 입력한다. 복원 후 다시 금고를 열어 프로젝트와 기억을 확인한다. 기존 금고를 가진 프로필에서는 덮어쓰기 복원을 허용하지 않는다.

### 실제 답변 확인

양쪽 서비스에서 각각 **새 대화**를 열고 다음 문장을 한 번 보낸다.

> 지난번 정한 조건대로 겨울 캠페인의 다음 작업을 진행해줘.

1. 앱의 해당 서비스 연결에 **맥락 조회 확인**이 나타났는지 보고, 채팅의 도구 호출 기록에서 `get_context`를 확인한다. 필요하면 앱·도구를 수동 선택해 연결을 진단할 수 있다. 자연어 요청만으로 호출된 경우와 수동 선택 후 호출된 경우를 따로 기록한다.
2. 답변이 세 줄 표로 **뉴스레터** 작업을 제시하는지 확인한다. 최초 값 “블로그”와 다른 프로젝트의 “비공개 봄 채널”이 섞였는지 본다. 다음 요청에 “이번 한 번은 목록으로”를 추가해 현재 요청이 우선하는지도 확인한다.
3. **선택한 연결 철회** 후 해당 서비스의 새 요청으로 조회가 거부되는지 확인한다. 금고 잠금·앱 종료 후에는 두 서비스 모두 새 조회가 차단되어야 한다. 이미 채팅으로 전달된 기억은 채팅에 남을 수 있으므로 차단 여부는 새 호출의 결과로 판정한다.
4. 앱 재시작·PC 재부팅·네트워크 변경 후 금고를 열고 **공개 연결 시작**으로 경로를 준비한다. 새 읽기 승인이 필요하다. 서비스가 예전 OAuth 등록을 재사용해 오류를 표시하면 앱의 **잠금·재시작 후 다시 연결하는 방법**을 따라 해당 Growth Brain 등록만 다시 만든다.
5. 앱을 닫고 같은 설치 파일을 다시 실행해 **예**로 재설치·업데이트한다. 금고와 프로젝트가 열리는지 확인한다. 제거 시험은 같은 파일의 **아니요**를 선택하고 제거를 확인한다. 재설치 후 같은 비밀번호로 기억이 복원되는지 확인한다. 기존 앱 파일이나 등록을 사용자가 수정한 경우에는 충돌을 표시하고 보존한다.

Windows 버전, 설치 파일 SHA-256, 서비스별 계정 종류와 등록 결과, 새 대화의 실제 도구 호출 여부, 예시 조건이 반영된 답변, 잠금·철회·재연결 결과를 기록한다. 비밀번호·인증 토큰·로그인 링크 대신 합성 예시의 결과와 오류 표시만 공유한다.
