# Windows 일반 사용자 설치·연결: 구현 전 조사와 검증 계획

2026-11-21. 보드 작업 `8e1cf5a3-d0d4-41e6-8ade-3708d6a969c3`.
복원 기준 `66a0b69d06330621ff4dbd48694b8dc9d66465d0`.
이 문서는 구현 전 계획이며 설치 산출물이나 Windows 지원 완료 증거가 아니다.

## 확인한 요구사항과 스펙 상태

ign8t에 실제 stdio 연결하여 get_project → get_documents(master_spec) → get_next_task →
get_task_context(위 작업)을 조회했다. 상세 설명과 완료 기준은 존재하지만 `spec_state=missing`이다.
마스터 1.0 전문은 읽었으며 stale 상태다. 최신 작업의 명시 승인·기기 암호화·제품 MCP 요구가
구 마스터의 자동 확정·서버 평문·입력창 주입보다 우선한다.

보드 응답의 task-loop 규칙은 완성된 스펙이 없으면 제품 코드 작성을 중지하고,
사용자가 스펙 없이 진행을 명시 허용한 경우에만 예외로 진행하도록 요구한다.
이 조사 이후 사용자가 유료 스펙 생성 없이 본 계획으로 제품 구현을 명시 허용했다.
현재 설치 및 실기기 시험 절차는 [Windows 시험 안내](windows-test-guide.md)를 따른다.
[개발 보드](https://www.ign8t.com/projects/b84c9058-644c-4dc0-a0cd-5a2eb9d017f9/backlogs).

일반 사용자에게 Git/Codex/Node/Python/WSL 설치, 빌드, 터미널, 설정 파일 편집,
서버 실행, 인증서 발급, DNS·포트포워딩을 요구하지 않는다. ChatGPT와 Claude 일반 웹 채팅
둘 다 대상이다. CLI 등록이나 수동 기술 설정 성공은 이 작업의 완료가 아니다.

## 코드에서 확인한 차이

| 영역 | 현재 구현 | 필요한 후속 |
| --- | --- | --- |
| 배포 | `scripts/package-release.py`: 확장 ZIP·소스 tar.gz | 런타임을 포함한 사용자별 Windows 설치·업데이트·제거 산출물 |
| 금고 접근 | `src/secure-files.ts`, `src/vault.ts`: Unix 소유자·mode·NOFOLLOW 검사 | Windows SID/DACL, reparse point, 원자적 저장·복구 보장 검증. 기존 검사를 단순 생략하지 않음 |
| 로컬 IPC | `src/broker.ts`: memory.sock, chmod, uid 검사 | 사용자 제한 IPC와 실제 접근 거부 검사. 기본 named pipe 권한이 안전하다고 가정하지 않음 |
| 사용자 조작 | `src/cli.ts`: TTY 필수, 비표시 입력, CONNECT/ALLOW | 로컬 신뢰 UI에서 생성·잠금 해제·복구·연결 범위 승인. HTTP/MCP에 비밀번호 입력 기능을 추가하지 않음 |
| 수집 연결 | `scripts/native-integration.py`: 셸 launcher | 사용자 범위 Windows native host 등록, 소유 기록·충돌 거부·기존 설정 보존 |
| 웹 연결 | `src/web-mcp.ts`: 기기 HTTPS, 파일 인증서; `src/web-auth.ts`: 메모리 동의·토큰 | 외부 도달 경로·인증서 수명주기 자동화, 재시작 후 재승인 안내 |
| 출시 검증 | `.github/workflows/ci.yml`: Linux | Windows 설치·실행·업데이트·제거와 두 웹 AI 실제 도구 호출·결과 검증 |

특정 앱 프레임워크·터널 공급자는 아직 선정하지 않았다. 호환성과 사용자별 보안 경계를
검증한 뒤 선택한다. WSL 요구나 클라우드 TLS 종료 프록시를 대안으로 고정하지 않는다.

## 구현 순서와 합격 기준

1. Windows 실행 기반: 지원 버전·아키텍처와 표준 사용자 권한을 명시하고 런타임 패키징,
   파일 권한·IPC를 구현한다. 개발 도구 없는 Windows에서 생성·재시작·잠금·복구를 검증한다.
   다른 OS 사용자의 접근 거부, 기존 파일 충돌, 손상·실패 시 보존을 검사한다.
2. 로컬 안내 UI: 금고 생성/잠금 해제·선택형 복구·프로젝트 선택·연결 승인·철회를 연결한다.
   비밀 입력은 기기 내에서만 처리하고, 임의 웹 콘텐츠가 로컬 특권 API를 호출하지 못하게 한다.
   승인 대기/실패/잠김/오프라인/차단/만료를 구분한다. 새 비밀 전달 경로는 별도 위협 검토한다.
3. 기기 TLS 연결 자동화: 기기에서 키 생성·인증서 갱신, 외부 HTTPS 경로를 자동 관리한다.
   중계가 필요하면 TLS 바이트만 전달하고 기기에서 종료한다. 공급자·도메인·운영 비용과
   필요한 권한을 확인하고, 실제 서비스 프로비저닝·배포는 별도 승인 범위로 남긴다.
   네트워크 변경·인증서 만료·연결 장애를 검증한다. 준비되지 않은 경로는 연결 완료로 표시하지 않는다.
4. 양쪽 서비스 연결: 최신 공식 연결 방식과 계정/워크스페이스 권한을 각각 확인한다.
   지원 API로 가능한 자동 등록과 서비스 로그인·승인 등 사용자 조작을 구분한다.
   기존 OAuth·범위 검사·금고 엔진을 재사용하고 우회·모든 턴 강제 호출을 약속하지 않는다.
5. 설치·업데이트·제거: 소유한 등록만 변경하며 사용자 수정·타 MCP/native 등록·금고를 보존한다.
   실패·재실행·버전 변경·재부팅을 검증한다. 설치 실행에는 관리자 권한을 기본 요구하지 않는다.
   게시자 서명·배포 및 관리 정책이 필요하면 그 조건을 그대로 안내한다.
6. 실제 수용 검사: 각 서비스의 새 일반 채팅에서 자연어 요청 → 실제 get_context →
   승인 선호도와 최신 프로젝트 결정이 반영된 결과물을 확인한다. 우선순위·다른 프로젝트 차단,
   미승인/폐기 기억 제외, 잠금·철회·앱 종료 후 접근 차단까지 검증한다.

## 최종 사용자 조작 목표

앱 설치/실행 → 로컬 금고 생성 또는 잠금 해제 → ChatGPT/Claude 선택 → 필요한 서비스 로그인 →
공통 또는 한 프로젝트의 읽기 범위 승인 → 일반 채팅에서 자연어로 작업 요청.
수집을 원할 때만 확장 설치와 사이트별 프로젝트·수집 동의를 별도로 수행한다.
재부팅 후 잠금 해제 및 필요한 재승인은 UI에서 한다. 저장·복호화·검색은 사용자 기기에 남지만,
AI에 전달한 기억은 해당 AI 서비스가 읽을 수 있음을 승인 화면에 설명한다.

## 완료 증거와 현재 한계

Windows 버전·표준 사용자 권한·설치 파일 해시·남은 사용자 조작·설치/업데이트/제거 결과,
두 서비스의 계정 조건·실제 도구 호출과 개인화 결과·잠금/철회/재연결 결과를 기록해야 한다.
합성 데이터만 사용하고 비밀번호·토큰·개인키나 실제 사용자 금고를 개발 환경으로 가져오지 않는다.

이번에는 브랜치 복원, 보드·마스터 독해, 코드 정적 조사와 계획 작성만 수행했다.
Windows 기기/설치 산출물, 공인 인증서 경로, 최신 플랫폼 지원 조건, 실제 AI 결과는 검증하지 않았다.
제품 코드는 변경하지 않았으므로 새 기능 검증이나 기존 전체 테스트 통과를 주장하지 않는다.
프로덕션 배포·환경 게시·확장 게시·DB 변경 없음.
