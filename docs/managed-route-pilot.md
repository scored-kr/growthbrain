# 계정 기기의 웹 연결 발급

계정 모드에서 사용자가 AI 연결을 시작하면 앱이 로그인 세션으로 기기 등록을 요청한다. 기존 기기 등록이 유효하면 재사용한다. 등록한 기기는 인증서를 발급·갱신하고 기기 안에서 TLS를 종료한다. 웹 서비스의 읽기 범위 승인은 해당 기기에서 직접 진행한다. 계정을 쓰는 경로에는 사용자의 Tailscale 로그인이나 서버·도메인·인증서 설정 단계가 없다.

## 시험 운영자의 준비

이 저장소에는 설치기에 포함되는 기기 코드와 운영자 검토용 발급 함수·SQL이 있다. 현재 작업에서 발급 서비스 배포와 실제 키 발급은 수행하지 않았다. 기존 Supabase 카탈로그와 프로젝트 정책을 확인한 뒤 별도로 승인한 환경에서 두 구성 요소를 준비해야 한다. 가입·동기화 연결의 준비 상태와 발급 서비스의 준비 상태는 각각 확인한다.

1. 한 Growth Brain 시험 계정에 운영자가 관리하는 별도의 시험용 tailnet을 배정한다. 꺼진 임시 기기의 호스트 이름을 다른 고객이 다시 가져갈 수 있는 공유 tailnet은 이 시험 구성에서 지원하지 않는다. 같은 계정의 승인된 기기는 서로 신뢰한다. 기존 개인/조직 tailnet을 재사용하거나 다른 업무 기기를 여기에 연결하지 않는다.
2. 운영자는 관리 화면에서 HTTPS 인증서와 Funnel을 준비한다. `tag:growthbrain-device`에 공개 TCP 443 Funnel 권한을 부여하고, 시험 기기 사이의 연결 및 내부 인프라·서브넷·출구 노드에 대한 접근을 차단한다. 기본 allow-all 규칙을 검토한다. OAuth 클라이언트에는 이 태그의 기기 등록에 필요한 `auth_keys` 쓰기 범위만 허용한다. `devices`, `policy_file`, 키 발급자 관리 권한은 필요하지 않다. [Tailscale Funnel](https://tailscale.com/kb/1223/funnel) · [API 명세](https://tailscale.com/api)
3. 운영자 전용 함수 `growthbrain-route-enroll`의 후보 소스는 `scripts/proposed/growthbrain-route-enroll/`에 있다. 함수는 `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`와 비밀 저장소의 `GROWTHBRAIN_ROUTE_TENANTS`를 사용한다. 마지막 값은 항목마다 `accountId`, `tailnet`, `clientId`, `clientSecret`이 있는 JSON 배열이다. 운영자는 검증된 계정 UUID와 해당 OAuth 클라이언트가 소유한 tailnet의 고유 이름을 매핑한다. 중복 계정·tailnet·클라이언트 설정은 거부한다. 요청/응답 본문, 인증 헤더 및 외부 OAuth 응답의 로그 수집을 끈다.
4. 승인된 환경에서 전용 등록 한도 계약 `scripts/proposed/route-enrollment-v1.sql`을 별도로 검토한다. 발급 함수는 Supabase Auth에서 사용자와 이메일 확인 상태를 재검증한다. 서버가 확인한 UUID에 대해서만 service-role 전용 RPC로 발급 횟수를 먼저 예약한다. 한 계정의 최근 30일 등록 기기 수는 5개, 하루 발급 시도는 24회, 전체 발급 시도는 하루 500회로 제한한다. 같은 계정·요청 UUID는 30일 동안 한 번만 소비한다. 결과가 불확실한 재시도는 이전 키를 되돌려 주거나 중복 발급하지 않는다.
5. 기기 등록 키는 한 번 쓸 수 있고, 지정한 태그·임시 기기·5분 만료 조건을 모두 만족한 제공자 응답만 전달한다. 기기 TLS 개인키·원문·금고 비밀은 발급 요청에 포함하지 않는다. 발급 API는 인증 후 키를 받아 든 같은 사용자의 다른 프로세스를 물리적으로 구별하지 못한다. 기기 수 한도는 하드웨어 인증이 아닌 등록 요청 식별자 기준이므로 전용 tailnet과 제한된 권한이 필요하다.

## 실패와 시험

미배정 계정·준비되지 않은 발급 서비스·정책 차단·한도 초과 시 앱에 오류가 표시된다. 계정 모드에서 개인 Tailscale 로그인으로 전환하지 않는다. 자격 만료로 새 기기 등록이 필요하거나 제공자가 공인 주소를 재할당한 경우, 앱에서 확인한 주소로 해당 플랫폼 연결을 다시 등록하고 범위를 승인한다. Tailscale과 인증서 투명성 로그에는 기기 호스트 이름 등 연결 메타데이터가 남을 수 있다.

`test/managed-route.test.mjs`는 합성 사용자·제공자 응답과 실제 PostgreSQL 엔진으로 역할 거부, 재발급 거부, 기기/발급 한도, 태그·유효 기간 검사를 수행한다. Go 테스트는 명령줄·인증 링크 입력 없이 등록 자격이 전용 파이프로만 전달되는 첫 등록 분기를 확인한다. 실사용 수용 시험에는 운영자가 준비한 격리 tailnet·발급 함수, 실제 사용자 계정과 공개 인증서, Windows 및 양쪽 웹 클라이언트의 결과가 필요하다.
