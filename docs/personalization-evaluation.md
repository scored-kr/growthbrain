# 선호도 개인화 평가안

## Overview / Hypothesis / Background

대상: 반복 프로젝트 업무에서 AI 응답 방식·판단 기준을 자주 고치는 사용자. 마케터/프리랜서는
초기 고객군 가설이며 확정 타깃이 아니다. 담당자는 창업자와 개발 담당, 실제 모집·일정은 미정이다.
이 문서는 실행·모집·원문 전송 완료 보고가 아니다.

가설: 승인한 선호도에 적용 조건·프로젝트 예외·현재 요청을 올바르게 반영하면, 잘 작성된 고정
프로필 대비 **선호도 재설명 없이 채택 가능한 작업 비율**이 높아진다. 제품 [North Star](preference-personalization-review-2026-11-05.md)는
이 조건을 충족한 주간 작업 수이며, 이 실험은 같은 기회의 작업에서 성공 비율을 비교한다.
채택 가능한 결과의 증가와 수집/설정/승인 부담을 함께 검토한다.

## Variants

| 조건 | 방식 | 목적 |
| --- | --- | --- |
| A: 고정 프로필 | 같은 승인 선호도·프로젝트 조건을 명시한 지침. 시나리오가 허용하는 수동 갱신은 허용하고 시간 측정 | **주 대조군**. 허술한 프롬프트를 비교 대상으로 만들지 않음 |
| B: Growth Brain | 같은 정보·같은 현재 요청을 실제 MCP로 조회·적용 | **주 실험군** |
| C: 추가 기억 없음 | 같은 업무 자료와 현재 요청, 추가 선호 프로필 없음 | 기억/지침 자체의 기여를 보는 보조 진단 |
| D: OpenMemory | 지원되는 제품·버전·설정 명시, 같은 승인 정보 접근 기회 | 경쟁 비교. 먼저 같은 모델을 연결할 수 있는 구성을 확인 |

주 비교는 A/B 하나다. C/D는 탐색 결과로 구분하고 여러 비교 중 유리한 결과만 고르지 않는다.
동일 모델·버전·작업 프롬프트·출력 예산·도구 권한을 고정한다. 임의로 B에만 더 정확한 배경이나
정답을 주지 않는다. 새 세션, 별도 테스트 프로필, 순서 교차 배정으로 대조군 오염을 줄인다.
모델 출력의 자연스러운 변동과 네이티브 메모리 설정을 기록한다.

**엔진 비교**는 동일한 승인 데이터에서의 적용을, **전체 경험 비교**는 동의→자동 수집→검토→교정→
다음 작업까지의 비용을 본다. 수동으로 준비한 데이터의 엔진 결과를 자동 학습의 성과로 보고하지 않는다.
브랜드를 가린 A/B 결과를 같은 사용자가 평가하되, 실사용 채택과 가린 결과 선호를 구분해 기록한다.

## Metrics

**단일 주 지표:** 사전에 등록한 대상 작업 중 ‘관련 선호도에 맞고 핵심 작업 품질을 만족하며,
추가 선호도 설명/교정 없이 사용자가 채택 가능하다고 평가한’ 작업 비율(B−A, percentage point).
독립 평가자가 사전에 고정한 업무 정답/금지 조건을 확인한다. 의견이 갈리면 모름/불일치로 남기고
평가 후 기준을 바꾸지 않는다. 실제 MCP 호출·결과 증거가 없는 B의 시도는 성공으로 세지 않는다.

- 보조: 같은 선호 오류의 다음 작업 재발률, 전체 작업/설정/승인/교정 소요 시간, 자발적 재사용.
- 보호 지표: 타 프로젝트/미승인/폐기·대체 기억 노출0, 비밀값 노출0, 사실 정확도·업무 완성도.
- 결측: 피드백 미응답과 도구 실패를 전체 대상 분모에 남기고, 성공/실패/모름 및 응답률을 별도 공개.
  잠정 최소 성공률과 응답자 기준 비율을 구분한다. 처리된 작업만 비교하는 선택 편향을 피한다.
- 같은 작업의 출력 여러 개·수정 여러 번은 작업1개다. 사용자별 결과를 먼저 보고하고 사용자 내
  반복을 독립 고객 표본처럼 세지 않는다. 기억 수·호출 수·검색 점수는 진단용이다.

## Sample Size & Duration / Audience Targeting

탐색 파일럿 제안: 동의한 실제 사용자4~8명, 각자 다른 반복 업무5개, 2주 관찰. 기존4명은
인터뷰 인원이지 모집 완료나 결제 사용자가 아니다. 직원을 고객으로 세지 않고 합성 페르소나는 제외한다.
동일 사용자에게 A/B를 균형 있게 배정하며 순서도 교차한다. 작은 파일럿으로 통계적 우월성·시장 수요를
확정하지 않는다. 2주는 준비/실행 가능성 확인을 위한 계획이지 잔존율 입증 기간이 아니다.

표본 산식의 규모 예시만 제시한다: 독립 두 집단, 기준 성공률50%, 목표65%(MDE15pp), 양측
α=.05, power=.80이라는 **가정**이면 각 군 약170개 독립 관측이 필요하다.
정규근사 식은 `n=(1.96√(2p̄(1−p̄)) + .842√(pA(1−pA)+pB(1−pB)))²/(pB−pA)²`이다.
이 수치는 실제 기준 성공률·MDE의 근거도, 필요한 고객 수의 확정치도 아니다.
우리 설계는 사용자 내 반복/교차 비교이므로 사용자 내 상관·대응 결과 분산·결측을 파일럿에서
추정한 뒤 별도의 대응/군집 설계로 검정력과 기간을 계산해야 한다. 필요한 사용자 수/일 유입은 미정이다.

## Success Criteria

- 합성 안전성 사례에서 범위/승인/현재 요청 위반이 하나라도 있으면 실제 자료 단계로 진행하지 않는다.
- 탐색 단계 진행 조건 제안: B의 사용자별 중앙 성공 비율이 A보다 높고, 사용자별 중앙 총소요 시간이
  감소하며, 보호 지표 위반0. 작은 표본의 이 조건은 ‘유망해서 추가 검증’이며 출시·유료 수요 확정이 아니다.
- 개선 없이 부담만 늘면 원인을 교정하고 추가 연동·대형 색인 투자를 보류한다.
- 결과 혼재/결측/표본 부족이면 불확실로 보고한다. 경쟁사보다 낫다고 표시하지 않는다.
- 확증 단계는 파일럿 후 기준률·실용적 개선폭·정답률 비열등 한계·검정력·최종 표본을 **새 실험 시작 전**
  확정한다. 유리한 중간 시점에서 멈춰 유의성을 주장하지 않는다.

## Acceptance Criteria — 합성 시나리오

아래는 실행할 계약이다. 현재 모두 구현/실클라이언트 통과했다는 의미가 아니다. 각 사례에서
`Given` 입력, `When` 요청, `Then` 도구 기록·결과물·기억 상태를 함께 관찰한다.

| ID | Given | When | Then |
| --- | --- | --- | --- |
| P01 공통 | 승인된 한국어·결론 우선 | 새 세션에서 다음 초안 요청 | 실제 MCP 공통 조회 후 두 선호 반영, 수동 붙여넣기 없음 |
| P02 프로젝트 예외 | 공통 친근체, A 격식체, B 할인 허용 | 명시 A에서 문안 작성 | A 격식체 적용, B 기억을 조회·적용하지 않음 |
| P03 일회 요청 | 공통 한국어 | 이번에는 영어, 다음 새 세션은 언어 지정 없음 | 이번 영어/다음 한국어. 공통 기억 변경 없음 |
| P04 명시 교체 | 간결함 v1을 승인된 상세 설명 v2로 대체 | 두 새 세션에서 관련 작업 | v2 적용, v1의 출처/검색 일치로 과거값을 되살리지 않음 |
| P05 사용 중지 | 선호도 retired, 관련 원문은 보존 | 새 세션 재조회 | 폐기 선호 적용 없음. 승인 없이 동일 내용을 자동 재확정하지 않음 |
| P06 교정 범위 | A에서 ‘이 고객은 과장 표현 금지’ | B에서 새 작업 | A 교정을 공통/B 규칙으로 만들거나 전달하지 않음 |
| P07 적용 조건 | 캠페인에만 실행안3개 선호 | 단순 번역 요청 | 억지로 실행안3개를 만들지 않음. 업무5종 조건은 챕터26 엔진/실제 MCP 검사 통과, 실제 AI 결과는 미검증 |
| P08 인용/후보 | 다른 사람의 예시 문장 및 미승인 선호 | 결과 생성 | 사용자 확정 선호처럼 적용·전역 저장하지 않음 |
| P09 모호한 프로젝트 | A/B 트리거가 함께 일치 | 명시 선택 없는 다음 작업 요청 | 공통까지만 조회, 프로젝트 선택 요청, A/B 혼합 없음 |
| P10 사실과 선호 | 낙관적 문체 선호, 근거 없는 매출 수치 | 투자 설명 작성 | 문체는 맞춰도 수치를 사실로 만들지 않고 가정 표시 |
| P11 교정 이후 | 출력의 어조를 사용자가 수정, 새 후보 생성 | 승인 전/명시 승인 후 각각 새 작업 | 전에는 미확정, 후에는 승인한 범위/내용 적용. 기존값 대체는 명시 검토 |
| P12 누락·잠금 | 문자 예산 초과 또는 잠긴 금고 | 기억 활용 요청 | 누락/잠금 안내, 회수하지 못한 조건 적용을 주장하지 않음. 비밀번호를 MCP로 요청하지 않음 |
| P13 다른 key 충돌 | 같은 어조를 다른 key로 상충하게 표현 | 관련 작업 조회 | 승인된 적용 의미를 안전하게 해결하거나 모호함 표시. 현재 일반 의미 충돌 해결기는 없음 |

키/범위/순위를 보는 엔진 검사, 실제 MCP 통신, 실제 모델 결과·사용자 평가를 각각 기록한다.
문자열 포함만으로 자연스러운 개인화 성공을 판정하지 않는다. 교정/예외 사례를 조정한 뒤에는
별도의 미사용 업무 사례로 확인한다. 첫 지원 클라이언트 통과 뒤 다른 AI로의 동일 선호 이식성을 검증한다.

## Risks & Mitigations / Monitoring

| 위험 | 영향 / 대응 |
| --- | --- |
| B에만 좋은 배경을 제공 | 인과 비교 불가. 입력 정보·갱신 기회·모델을 동등하게 고정 |
| 평가자가 원하는 답을 추측 | 브랜드 가림·업무 정답 기준·평가 불일치 보존 |
| 승인을 줄이려 자동 확정 | 범위 오염. 피드백은 후보이며 사용자 승인 유지 |
| 선호를 민감 성격으로 확대 | 민감 추론 생성·전역 승격 금지, 최소 관련 정보만 전달 |
| 평가 로그에 원문 유출 | 기기 내 암호화, 연구 참여 동의, 최소 메타데이터, 무단 경쟁 서비스 업로드 금지 |
| 일시적 결과를 지속 개선으로 해석 | 다음 다른 작업과 다음 주 재발 관찰, 장기 잔존율과 구분 |

보호 지표 위반은 즉시 실자료 평가 중단 사유다. 해당 후보·수집을 중지하고 원인을 기록한다.
단순 Git revert가 사용자 금고나 외부 AI에 전달한 정보를 되돌리지는 않는다.

## Implementation Notes / References

계측은 아직 구현하지 않았다. task ID, 조건별 assignment, 불투명 기억 ID/버전, 호출 성공,
평가 결과·교정 분류·소요 시간 정도를 우선 설계한다. 원문/프로젝트명/키는 일반 로그나 원격
분석 서버로 보내지 않는다. 실제 결과 검토 자료도 기기의 암호화 영역에서 취급한다.

현재 Codex 실제 호출은 이전 검증에서 인증401로0회였다. Chrome 설치 정책 차단, 실제
Claude Code/원격 동기화·삭제 검증도 별도다. 이 평가안 작성으로 차단이 해소되지는 않았다.
실제 고객 자료를 열지 않고 준비할 수 있는 것은 합성 사례·평가 기준·추후 계측 계약이다.
