# 로컬 기억 관리 화면

Chrome 확장 팝업의 **기억 관리 열기**에서 확장 소유 관리 탭을 연다. 사용자 기기의 native host와 잠금 해제된 금고가 필요하다. 웹 서버에 기억을 올리거나 비밀번호를 입력하는 화면이 아니다.

- 현황: 공통 + 선택한 프로젝트의 확정 기억·핀·후보·인계 후보·수집 메시지 수. 실제 금고에서 집계하며 AI 호출 횟수나 개인화 성과를 만들어 표시하지 않는다.
- 검토 대기: 출처·원문·변경 사유·작업 범위를 확인해 승인/기각한다. 기존 기억 교체는 별도 체크가 필요하다. 수정은 새 후보를 만들고 다시 승인해야 한다.
- 확정 기억: 중요 기억 고정/해제와 사유를 남기는 사용 중지. 핀은 현재 요청과 프로젝트/작업 필터를 우회하지 않는다.
- 맥락 인계: 목표·완료 주장/근거·차단 사유·다음 작업·유효 기한. 승인 시 근거 검토와 기존 인계 교체를 별도로 확인한다.
- 수집 기록: 현재 프로젝트의 웹·Codex·Claude Code 수집 원문을 필요한 때 펼쳐 확인한다.
- 전달 맥락 확인: 이번 요청과 작업 유형을 적용한 로컬 미리보기. AI에 전달하거나 실제 도구 호출 증거로 계산하지 않는다.
- AI 연결 안내: ChatGPT/Claude의 HTTPS MCP 연결과 로컬 권한 승인, 실제 도구 호출 + 결과물 확인 방법. 앱 로그인/원격 동기화/회원 데이터 삭제는 아직 연결되지 않았음을 표시한다.

프로젝트·화면 전환 시 이전 내용을 즉시 지우며 늦게 도착한 응답을 버린다. 브라우저 저장소에는 마지막 선택 프로젝트 UUID만 추가하고 기억·출처·이름을 캐시하지 않는다. 오류 시 낙관적으로 승인 완료를 표시하지 않으며 쓰기를 자동 재시도하지 않는다. 연결 확인은 10초 간격이며 잠금/연결 끊김 응답 시 열린 상세 내용을 포함해 지운다. 잠금 직후 브라우저 메모리가 즉시 보안 소거된다는 보장은 없다.

관리 명령은 정확한 확장 소유 `app.html`에서만 중계한다. 일반 AI 페이지의 content script는 조회·검토·핀·인계 API에 접근할 수 없다. 금고 잠금 해제·복구키·전체 삭제와 OAuth 승인 API는 관리 탭에 노출하지 않는다.

`Ctrl/⌘ K`는 프로젝트 선택, `Ctrl/⌘ B`는 메뉴 표시 전환이다. 상세 창은 기본 HTML dialog의 포커스 제한과 Esc 닫기를 사용한다. 1280px/320px에서 Chromium 렌더링·가로 넘침을 검사했다.

검증: `test/app-ui.mjs`는 실제 Chromium 화면 → 모의 Chrome runtime → 실제 native 프레이밍 → 실제 broker → 합성 암호화 금고로 승인·교체·수정·핀·인계·조회·잠금·프로젝트 응답 경합을 확인한다. 설치된 확장, 로그인된 ChatGPT/Claude, 실제 AI 개인화의 검증은 아니다.

기존 보드의 `packages/web`, Next/Fastify 서버 평문 조회, 자동 입력창 주입, 평문 IndexedDB 캐시는 현재 사용자 요구와 다르다. 현재 구현은 기존 `extension/`, `src/` 구조를 재사용하고 실제 AI 전달은 제품 MCP로 처리한다.

후보 검토창의 선택적 충돌 분석은 [로컬 추론](local-inference.md)이 사용자 터미널에서 켜진 경우에만 실행됩니다. 모델의 결과는 조언이며 사용자가 수정·별도 승인해야 합니다.
