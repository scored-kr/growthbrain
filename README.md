# Growth Brain

ChatGPT와 Claude 일반 채팅에서 상세페이지 원고의 채택안과 첫 문장 수정을 이어 쓰는 Chrome MV3 시제품입니다. Node.js 24와 npm을 사용합니다.

## 한 PC에서 확인하기

```sh
npm ci
npm run build
npm test
npm run test:browser
```

확장 설치가 허용된 Chrome에서 `chrome://extensions` → **개발자 모드** → **압축해제된 확장 프로그램을 로드**로 빌드된 `dist`를 엽니다. 확장 팝업에서 두 사이트의 **대화 수집**과 **원고 전달**을 각각 켜고, 이미 열려 있던 채팅은 새로고침합니다. 사이트 권한은 현재 Chrome 프로필에 적용됩니다. 공용 프로필에서 사이트 계정을 바꿀 때는 팝업에서 수집과 전달을 끕니다.

1. ChatGPT의 일반 채팅에서 상품명을 넣어 상세페이지 초안 세 가지를 요청합니다. 각 원고에 `1안:`, `2안:`, `3안:`처럼 번호를 붙이고, 2안의 두 번째 문장에 방금 만든 고유 문구를 넣어 달라고 합니다. 여러 단락으로 된 원고는 원고마다 코드 블록으로 둘러싸면 경계를 보존할 수 있습니다. 답변을 확인하고 **2안으로 확정**이라고 보냅니다.
2. Claude의 새 채팅에서 **어제 고른 2안의 첫 문장만 바꿔줘**라고 보냅니다. 연결한 서비스가 공식 MCP의 `get_context`를 호출할 수 있습니다. 요청별 호출을 확인할 수 없으면 입력창 위 **2안 조회 미확인 ⌄**에서 원고를 확인합니다. **2안과 함께 다시 보내기**를 누르면 원래 질문과 확인한 원고가 한 번 준비·전송됩니다. 입력창에 새 답장을 쓰고 있으면 보존합니다.
3. 답변의 첫 문장 이후가 고유 문구, 줄바꿈, 공백까지 원문과 일치하는지 확인합니다. Claude에서 **이 문장으로 확정**한 뒤 새 ChatGPT 채팅에서 **최신안을 보여줘**라고 요청합니다. 첫 문장만 받은 경우에도 확장에서는 확정 전 원고의 뒷부분을 그대로 이어 붙입니다.

인식할 수 있는 원고가 없거나 프로젝트가 경합하면 제출을 보류합니다. 사용자가 선택하지 않은 제안은 최신 확정안에 반영되지 않습니다. 현재 규칙은 번호가 붙은 한국어 원고와 명시적인 채택 표현을 지원합니다. 서비스 화면의 발화 ID·역할·편집기 구조가 바뀌면 해당 화면에서 다시 검증해야 합니다.

## 개발용 공식 MCP 연결

`npm run mcp`는 한 브라우저 프로필에 연결하는 개발용 중계 서버를 실행합니다. 기본 HTTP 리스너는 `127.0.0.1:43128`, 기기 연결은 `127.0.0.1:43127/device`입니다. 개발자는 비밀 관리 경로에서 실행마다 무작위 32바이트를 base64url로 인코딩한 `GB_DEVICE_TOKEN`을 설정하고, 확장 팝업의 **개발용 MCP 연결**에서 같은 기기 연결 키를 등록합니다. 키는 브라우저 세션에만 보관합니다.

실제 웹 서비스 등록에는 개발팀이 관리하는 HTTPS 주소가 필요합니다. 개발자는 `GB_PUBLIC_ORIGIN`에 주소를 설정하고 해당 주소로 수신하는 TLS 프록시를 HTTP 리스너에 연결합니다. 확장을 다른 PC에서 쓸 때는 개발팀이 빌드 시 `VITE_GB_DEVICE_ORIGIN`, 서버 시작 시 `GB_DEVICE_ORIGIN`을 동일한 WSS origin으로 지정하고 `/device` 업그레이드만 기기 리스너로 전달합니다. 사용자 PC는 이 주소로 아웃바운드 연결합니다. 인증서와 프록시는 개발팀이 관리합니다. 요청·응답 본문이나 토큰을 프록시 로그에 남기지 않습니다.

서비스의 사용자 지정 MCP 연결에 개발용 HTTPS 주소의 `/mcp`를 등록합니다. 브라우저에 표시된 요청 번호와 서버 터미널의 `requests` 결과를 대조합니다. 개발자는 팝업에 표시된 프로젝트 ID로 `approve <요청 번호> <프로젝트 ID>`를 실행합니다. 서비스는 OAuth와 PKCE로 승인된 한 프로젝트를 읽을 수 있습니다. 확장은 질의를 강제하지 않으며 최근 서비스 조회만으로 특정 채팅에서 원고를 썼다고 표시하지 않습니다.

## 검증 범위

- `npm test`는 기억 규칙 및 SDK 클라이언트로 제품 서버의 OAuth·MCP 경로를 검사합니다. 테스트에서 채팅 발화와 권한을 부여받은 클라이언트는 합성 입력입니다.
- `npm run test:browser`는 Chromium에서 모의 채팅 화면, 빌드된 팝업·콘텐츠 스크립트·백그라운드 코드, 실제 IndexedDB와 Web Crypto를 사용합니다. Chrome 확장 API는 테스트 어댑터로 제공합니다. `npm run test:installed`는 설치를 허용한 브라우저에서 압축해제 확장으로 같은 모의 채팅을 검사합니다.
- 로그인한 두 서비스의 일반 채팅에서 처음 고른 고유 문구와 변경된 첫 문장을 직접 대조해야 실사용 왕복을 확인할 수 있습니다.
- `npm run test:mcp-browser`는 같은 모의 채팅에서 공식 SDK → 제품 MCP → 상호 인증 WebSocket → 빌드된 확장 워커 → 암호화된 로컬 원고의 전체 경로를 검사합니다. 개발 터미널의 `reads`에는 서비스·프로젝트·버전과 응답 완료 시각만 남습니다.

## 두 번째 PC의 암호문 호환성

`npm run test:sync-browser`는 합성 계정과 서로 독립된 Chromium 프로세스 두 개로 복원을 검사합니다. 첫 브라우저가 실제 기억 엔진으로 2안을 확정·수정한 뒤 암호화하고 종료합니다. 두 번째 브라우저는 원래 비밀번호로 키 포장을 열고 최신 2안과 탈락한 1안을 조회합니다. 재설정한 비밀번호로는 이전 원고를 열 수 없습니다.

`sync/account-envelope.ts`는 복구 브랜치의 scrypt·HKDF·AES-GCM 형식을 사용합니다. 저장소에서 볼 수 있는 메타데이터는 무작위 금고 ID, 순번, 직전 리비전, 암호문 길이 등입니다. 운영 Supabase `Growth brain`의 스키마·회원별 정책 확인과 실제 계정 동기화는 별도 단계입니다. 현재 확장의 저장 위치는 이 Chrome 프로필의 IndexedDB입니다.
